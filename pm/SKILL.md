# 产品经理专家

## 概述

本技能提供完整的产品管理工作流，支持从需求评估到原型设计的全流程。

**工作方式**：七阶段渐进式工作流，每个阶段独立可控，用户确认后触发下一阶段。

**TFS 集成**：通过 **tfs-mcp MCP 服务器** 进行所有 TFS 操作（工作项获取、更新、附件上传）。

**Wiki 集成**：通过 **wiki-mcp MCP 服务器** 获取 Wiki 页面内容，作为需求分析的辅助参考材料。

**功能清单匹配**：自动根据产品名称匹配已有功能清单，判断需求是否为重复需求或已实现功能。

**代码分析与修改清单**：如果在分析过程中结合了代码进行分析，分析完成后需要列出修改清单（可选）。

**强制人工确认原则**：
- 功能清单未找到时，必须使用 `AskUserQuestion` 让用户明确选择
- 禁止自动跳过或自行决定继续

## 七阶段工作流

| 阶段 | 名称 | 输出文件 |
|------|------|----------|
| 0 | TFS 需求获取 | 获取 TFS 工作项内容 |
| 0.5 | Wiki 内容获取 | 获取 Wiki 页面内容（可选）|
| 0.6 | 创建AI分析任务 | TFS 子任务（AI分析任务） |
| 1 | 需求评估 | `过程文件/[需求号]/[需求号]_需求设计_01_需求合理性评估报告.md` |
| 2 | 需求补充 | 更新评估报告 |
| 3 | 需求PRD设计 | `过程文件/[需求号]/[需求号]_需求设计_02_功能需求.md` |
| 4 | 原型设计 | 前端代码 + `过程文件/[需求号]/[需求号]_需求设计_03_原型说明.md` |
| 5 | TFS分析 | `过程文件/[需求号]/[需求号]_需求设计_04_TFS需求分析.md` |
| 6 | TFS上传 | 更新TFS需求分析字段 + 上传附件（可选）|
| 6.5 | 完成AI分析任务 | 分析内容写入任务详情 + 状态改为已解决 |

> **重要**：
> - 所有输出文件存储在**当前工作目录下的** `过程文件/[需求号]/` 子目录
> - TFS 工作项使用工作项 ID 作为目录名和文件名前缀
> - 手动输入需求使用年月日作为目录名和文件名前缀

## 阶段0: TFS 需求获取（可选）

### 前置条件

**tfs-mcp 配置是必须的**。如果未配置：
- 无法从 TFS 获取工作项
- 用户需要手动提供需求内容

### 触发条件
用户提供 TFS 工作项 ID 或需求号

### 输入格式
```
工作项 ID: [数字编号]
```

### 处理流程

#### 步骤1: 调用 tfs-mcp 获取工作项

使用 MCP 工具: `mcp__tfs-mcp__tfs_get_workitem`

**返回字段**:
| 字段 | 说明 |
|------|------|
| `id` | 工作项 ID |
| `title` | 需求标题 |
| `type` | 工作项类型 |
| `state` | 当前状态 |
| `description` | 需求描述 |
| `priority` | 优先级 |
| `assignedTo` | 指派人 |
| `tags` | 标签 |

#### 步骤2: 将状态从"已建议"改为"活动"

获取工作项成功后，如果当前状态为"已建议"，则自动将状态更改为"活动"：

```javascript
mcp__tfs-mcp__tfs_change_state({
  id: 1445554,
  state: "活动"
})
```

#### 步骤3: 处理获取失败

如果 tfs-mcp 调用失败（未配置或工作项不存在），提示用户手动输入：
```
无法从 TFS 获取工作项，请手动提供需求内容：

①背景：[业务背景说明]
②需求：[具体需求描述]
```

#### 步骤4: 用户确认需求

**必须使用 AskUserQuestion 工具弹出确认对话框**。

## 阶段0.6: 创建AI分析任务

### 触发条件
阶段0成功获取到TFS工作项。手动输入需求时不触发。

### 前置数据
- 父工作项ID（阶段0产出）
- 父工作项的 `iterationPath` 字段
- 父工作项的 `assignedTo` 字段
- 项目名称（从工作项所属项目获取）

### 处理流程

#### 步骤1: 创建子任务

使用 `mcp__tfs-mcp__tfs_create_workitem` 创建任务：

```javascript
mcp__tfs-mcp__tfs_create_workitem({
  project: "{PROJECT_NAME}",
  workItemType: "Task",
  title: "AI分析任务:{需求标题}",
  parentWorkItemId: {DEMAND_ID},
  assignedTo: "{父需求的 assignedTo}",
  iterationPath: "{父需求的 iterationPath}",
  fields: {
    "Microsoft.VSTS.Scheduling.OriginalEstimate": 1
  }
})
```

#### 步骤2: 激活任务

将任务状态从"已建议"改为"活动"：

```javascript
mcp__tfs-mcp__tfs_change_state({ id: ANALYSIS_TASK_ID, state: "活动" })
```

#### 步骤3: 保存任务ID

保存 `ANALYSIS_TASK_ID` 供阶段6.5使用。

### 错误处理
- 创建失败时记录警告，继续执行后续阶段（降级：阶段6.5不执行）
- 最多重试3次，每次间隔5秒

## 阶段0.5: Wiki 内容获取（可选）

### 前置条件

**wiki-mcp 配置**。如果未配置，将跳过此阶段。

### 触发条件

需求内容（TFS 工作项描述或用户手动输入）中包含 Wiki URL。

### Wiki URL 识别规则

匹配以下任一模式的 URL：
- `pageId=数字`（如 `pageId=12345`）
- `/pages/数字`（如 `/pages/12345`）
- `/display/空间Key/`（如 `/display/DEV/页面标题`）
- 公司 Wiki 域名（如 `winwiki.winning.com.cn`）

**正则表达式**：
```regex
(pageId=\d+|/pages/\d+|/display/\w+/|wiki\.company\.com)
```

### 处理流程

#### 步骤1: 提取 Wiki URL

从需求描述中使用正则匹配提取所有 Wiki URL，去重后得到 URL 列表。

#### 步骤2: 获取 Wiki 页面内容

使用 wiki-mcp 工具获取页面内容：

```javascript
mcp__wiki-mcp__wiki_get_page({
  pageIdOrUrl: "http://wiki.company.com/pages/viewpage.action?pageId=12345",
  embedImages: false  // 不嵌入图片，节省 token
})
```

**返回字段**：
| 字段 | 说明 |
|------|------|
| `id` | 页面 ID |
| `title` | 页面标题 |
| `spaceKey` | 空间 Key |
| `spaceName` | 空间名称 |
| `content` | Markdown 格式的页面内容 |
| `url` | 页面 URL |
| `lastUpdated` | 最后更新时间 |

#### 步骤3: 整合到分析上下文

将获取的 Wiki 内容作为辅助材料整合到后续分析流程中：

| 后续阶段 | Wiki 内容用途 |
|----------|--------------|
| **阶段1（需求评估）** | 了解业务背景、现有方案、设计规范 |
| **阶段3（功能设计）** | 参考已有功能文档、接口规范 |
| **阶段4（原型设计）** | 遵循 UI/UX 设计规范 |
| **阶段5（TFS 分析）** | 补充技术细节、实现方案 |

#### 步骤4: 在文档中引用 Wiki 来源

在生成的评估报告和需求文档中，添加 Wiki 引用说明：

```markdown
## 参考文档
- [Wiki 页面标题](Wiki URL) - 获取时间：2024-01-01
```

### 常见 Wiki 内容类型

| Wiki 类型 | 分析用途 |
|-----------|----------|
| 设计规范 | 原型设计时遵循 UI/UX 规范 |
| 功能文档 | 参考已有功能设计模式 |
| 技术方案 | 了解技术实现细节和约束 |
| 业务流程 | 理解业务背景和流程 |

### 错误处理

- **Wiki URL 无法访问**：提示用户，继续使用已有信息进行分析
- **页面不存在**：跳过该 URL，记录警告信息
- **wiki-mcp 未配置**：跳过此阶段，不影响后续流程

## 阶段1: 需求评估

### 五维评估框架

| 评估维度 | 满分 | 评估要点 |
|----------|------|----------|
| **需求合理性** | 25分 | 业务逻辑自洽性、技术实现可行性、需求边界清晰度 |
| **需求必要性** | 25分 | 解决痛点程度、使用频率预期、用户覆盖范围 |
| **现有功能兼容性** | 25分 | 功能重复度、系统一致性、数据兼容性 |
| **新功能完整性** | 25分 | 功能点覆盖、输入输出明确、异常处理考虑 |
| **业务相关性** | 25分 | 战略契合度、业务条线关联、跨条线影响 |
| **总计** | **125分** | 综合评分 |

### 需求分级

| 等级 | 分数范围 | 处理方式 |
|------|----------|----------|
| **S级** | ≥100分 | 重要且紧急，启用快速通道 |
| **A级** | 80-99分 | 合理且必要，按正常流程 |
| **B级** | 60-79分 | 存在疑问，需要澄清后处理 |
| **C级** | <60分 | 不合理或不必要，建议驳回 |

### 输出文件

创建目录并生成评估报告：
```bash
mkdir -p "过程文件/[需求号]"
```

> **重要**：评估报告中的需求分级（S/A/B/C）将被记录，用于阶段6自动打标签。

### 代码分析（可选）

如果评估过程中需要结合现有代码进行分析（如判断功能是否已实现、评估技术可行性等）：

1. **分析时机**：在五维评估框架的"现有功能兼容性"维度评估时
2. **分析方法**：使用 `Grep`、`Read`、`Glob` 工具查看相关代码
3. **输出要求**：如果进行了代码分析，需要在评估报告中添加"代码分析"章节

#### 代码分析章节格式

```markdown
## 代码分析

### 分析范围
- 分析的代码路径：[文件路径列表]
- 分析目的：[判断功能实现/评估技术可行性等]

### 分析结论
[简要说明代码分析的发现]

### 修改清单（可选）

> 如果需求确认要实现，以下是需要修改的文件清单

| 序号 | 文件路径 | 修改类型 | 修改说明 |
|------|----------|----------|----------|
| 1 | src/views/xxx.vue | 新增 | 新增 XX 页面 |
| 2 | src/api/xxx.ts | 修改 | 新增 XX 接口 |
| 3 | src/components/xxx.vue | 修改 | 扩展 XX 组件功能 |

**修改类型**：新增、修改、删除、重构
```

## 阶段4: 原型设计

### 选择原型设计方式

使用 `AskUserQuestion` 让用户选择：

**选项A：WinDesign Next 风格原型（Vue 3 组件）**
- 使用 Vue 3 + win-design-next 组件库
- 输出：Vue 组件 + 原型说明文档

**选项B：Pencil 绘制原型（.pen 文件）**
- 使用 Pencil MCP 服务器
- 输出：.pen 文件 + 原型截图 + 原型说明文档

### WinDesign Next 技术规范

> **参考文档**: [design-standard.mdc](references/design-standard.mdc)

#### 设计稿标准尺寸
- **标准尺寸**: 1920 × 1080px
- **最小适配尺寸**: 1366 × 768px

#### 字体规范
- **基础字号**: 14px
- **小字**: 12px
- **标题**: 16px

#### 主题色
- **主题色**: `#2d5afa`
- **成功色**: `#00ab44`
- **警告色**: `#ff8c00`
- **错误色**: `#ec0000`

#### 间距规范
间距要求：`16px` `12px` `8px` `4px`

#### 组件使用规则（强制）
- 只能使用 **win-design-next** 组件库
- 组件标签必须以 `<w-` 开头（小写）
- 框架已全局注册，无需手动导入
- 严格禁止使用任何其他 UI 组件库

#### 代码示例
```vue
<template>
  <!-- 正确：使用 win-design-next 组件 -->
  <w-button type="primary">提交</w-button>
  <w-input v-model="value" />
  <w-table :data="tableData" :columns="columns" />
</template>

<script setup lang="ts">
// 正确：无需导入，开箱即用
</script>
```

### 目录结构
```
prototype-viewer/src/prototypes/[需求号]/
├── App.vue           # 主组件（入口）
└── [功能简写].vue    # 功能子组件
```

#### 修改清单格式

```markdown
## 四、修改清单

> 基于代码分析，以下是实现本需求需要修改的文件清单

| 序号 | 模块 | 文件路径 | 修改类型 | 修改说明 | 影响范围 |

**修改类型**：新增、修改、删除、重构
```

## 阶段6: TFS 上传（可选）

### 上传方式选择

使用 `AskUserQuestion` 让用户选择：
1. **完整上传**：更新TFS字段 + 上传附件 + 添加标签
2. **仅更新字段**：只更新需求分析字段 + 添加标签
3. **跳过上传**：不上传到TFS

### 上传文件列表
1. 需求合理性评估报告
2. 功能需求文档
3. 原型说明文档
4. TFS需求分析文档

### 处理流程

#### 步骤1: 读取评估报告获取需求分级

在打标签前，先从评估报告中读取需求分级：
```bash
# 读取评估报告
评估报告路径="过程文件/[需求号]/[需求号]_需求设计_01_需求合理性评估报告.md"

# 从报告中提取分级（S/A/B/C）
# 查找"分级结果"行
```

#### 步骤2: 更新 TFS 需求分析字段

使用 tfs-mcp 更新需求分析字段：

```javascript
mcp__tfs-mcp__tfs_update_workitem({
  id: 1445554,
  updates: {
    "Winning.Demand.Analysis": "需求分析内容..."
  },
  comment: "更新需求分析"
})
```

#### 步骤3: 添加标签 + 更改状态

```javascript
// 根据评估分级构建标签字符串（分号分隔）
// 从评估报告中读取分级（如：A级）
const gradeLevel = "A"; // 实际从文件读取
```

## 阶段6.5: 完成AI分析任务

### 触发条件
阶段0.6成功创建了 `ANALYSIS_TASK_ID` 时执行。如果阶段0.6失败或跳过，本阶段也跳过。

### 处理流程

#### 步骤1: 生成需求总结

从评估报告、功能需求、TFS分析中提炼一份面向开发的摘要，置于报告最顶部。格式：

```html
<h2>需求总结</h2>
<table>
<tr><th>需求标题</th><td>{标题}</td></tr>
<tr><th>业务背景</th><td>{一句话概述业务背景}</td></tr>
</table>
<h3>核心功能点</h3>
<ul><li>{功能点1}</li><li>{功能点2}</li>...</ul>
<h3>技术方案</h3>
<p>{技术方案概要}</p>
<h3>涉及仓库与模块</h3>
<table>
<tr><th>仓库</th><th>修改模块</th><th>修改说明</th></tr>
<tr><td>{仓库名}</td><td>{模块名}</td><td>{新增/修改/删除}</td></tr>
</table>
<h3>工作量估算</h3>
<p>预计开发工时：{X}人天，涉及 {N} 个仓库</p>
```

#### 步骤2: 汇总分析内容

将以下阶段的内容合并为一份完整的分析报告：
- 需求总结（步骤1生成）
- 阶段1：需求合理性评估报告（`过程文件/[需求号]/[需求号]_需求设计_01_需求合理性评估报告.md`）
- 阶段3：功能需求文档（`过程文件/[需求号]/[需求号]_需求设计_02_功能需求.md`）
- 阶段5：TFS需求分析（`过程文件/[需求号]/[需求号]_需求设计_04_TFS需求分析.md`）

#### 步骤3: 转换为HTML并更新任务

将汇总内容转换为HTML格式（与阶段6转换 `Winning.Demand.Analysis` 的方式一致），更新到任务的 description 字段：

```javascript
mcp__tfs-mcp__tfs_update_workitem({
  id: ANALYSIS_TASK_ID,
  updates: {
    "System.Description": "<h2>需求总结</h2>\n{摘要HTML}\n<h2>AI需求分析报告</h2>\n{详情HTML}"
  },
  comment: "AI分析完成"
})
```

#### 步骤4: 解决任务

将任务状态改为"已解决"：

```javascript
mcp__tfs-mcp__tfs_change_state({ id: ANALYSIS_TASK_ID, state: "已解决" })
```

### 错误处理
- 更新失败时记录警告，不影响主流程
- 最多重试3次
