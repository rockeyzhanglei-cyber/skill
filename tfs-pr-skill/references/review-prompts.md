# 代码评审 Prompt 参考

> 当需要更详细的评审 prompt 时参考此文件。

---

## 快速评审 Prompt

用于常规 PR 评审：

```
分析以下代码变更，关注：
1. 代码质量（可读性、复杂度、重复代码）
2. 最佳实践（SOLID 原则、错误处理）
3. 潜在问题（Bug 风险、安全漏洞、性能）
4. 具体改进建议

代码变更：
{code_changes}
```

---

## 深度评审 Prompt

用于复杂或重要的 PR：

```
您是一位经验丰富的软件架构师，负责对 PR 进行深度评审。

## 评审要求

### 1. 代码质量（权重 40%）
- 可读性：命名规范、代码结构、注释完整性
- 复杂度：圈复杂度、方法长度、嵌套深度
- 重复代码：是否存在可提取的公共逻辑
- 测试覆盖：是否有足够的单元测试

### 2. 最佳实践（权重 30%）
- SOLID 原则遵循情况
- 设计模式使用是否合理
- 错误处理和资源管理
- 依赖注入和解耦程度

### 3. 潜在问题（权重 30%）
- Bug 风险：边界条件、空指针、类型错误
- 安全漏洞：SQL 注入、XSS、敏感信息泄露
- 性能问题：循环效率、内存泄漏、数据库查询

## 代码变更
{code_changes}

## 输出要求
请按照 SKILL.md 中的评审报告格式输出，确保每个问题都指出具体的代码位置。
```

## 需求合规性 Prompt

用于检查代码是否满足需求：

```
检查代码实现是否满足工作项需求。

## 工作项信息
- 标题: {work_item_title}
- 描述: {work_item_description}
- 验收标准: {acceptance_criteria}

## 代码变更
{code_changes}

## 输出要求

逐项检查需求，输出表格：

| 需求点 | 状态 | 说明 | 代码位置 |
|--------|------|------|----------|
| {需求1} | ✅/⚠️/❌/🔍 | 实现情况 | file:line |

状态说明：
- ✅ 完全符合：需求已完整实现
- ⚠️ 部分符合：部分实现或实现不完整
- ❌ 不符合：实现与需求不符或缺失
- 🔍 待验证：需要人工验证（如 UI、业务流程）
```

---

## 使用时机

| 场景 | 推荐 Prompt |
|------|-------------|
| 小型 PR（<5个文件） | 快速评审 Prompt |
| 大型 PR 或核心模块 | 深度评审 Prompt |
| 有关联工作项 | 快速评审 + 需求合规性 Prompt |
| 安全敏感代码 | 深度评审 Prompt，重点关注安全 |
