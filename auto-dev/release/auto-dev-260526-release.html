📊 提示词 → 脚本：核心收益量化 架构对比

从"让 AI 理解意图并操作"到"让 AI 执行确定性命令"

v2.0 所有 TFS/MCP 操作依赖 AI 理解提示词后自行推理调用方式，参数构造、错误处理、轮询逻辑全靠提示词描述。
v2.1 将确定性操作收进 Python 脚本，AI 只需 $PYTHON scripts/xxx.py，脚本内部处理参数、重试、错误。

稳定性 — 最大提升 — TFS 参数构造、MCP 调用、轮询逻辑从 AI 推理变为脚本执行，消除参数拼错、步骤遗漏、轮询间隔不一致等随机性 核心
Token 节省 — 中等提升 — 每次 TFS 操作从"读描述→推理→构造参数→可能重试"(3-4步推理) 缩减为"执行一行脚本"(1步)。完整流水线约 15-20 次 MCP 操作，总计省 ~3K-10K token
错误恢复 — 显著提升 — 重试逻辑内置脚本（PR创建3次重试、任务创建3次重试+降级），不依赖 AI 理解 if-else 提示词
可调试性 — 显著提升 — stage-helper.py log 统一日志 + 状态文件，出问题直接看文件，不用翻 AI 对话历史
数据对比 — SKILL.md 40KB→50KB（+24%为脚本模板，非推理指令）；MCP 调用从 0 次标准化引用增至 76 次；TFS 操作引用从 10 处自然语言增至 50 处精确脚本调用
