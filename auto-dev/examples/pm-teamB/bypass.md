# pm-teamB bypass

auto-dev 全自动执行时的 bypass 策略。本技能基于标准 pm 技能简化，bypass 策略与标准 pm 一致。

| 阶段 | 正常交互 | auto-dev 策略 |
|------|----------|-------------|
| 阶段 0 获取需求 | AskUserQuestion 确认需求内容 | **跳过**，直接用 TFS 工作项内容 |
| 阶段 0.5 Wiki 获取 | 无交互 | 正常执行 |
| 阶段 0.6 创建 AI 分析任务 | 无交互 | 正常执行 |
| 阶段 1 需求评估 | 无交互（内部评分） | 正常执行 |
| 阶段 2 需求补充 | AskUserQuestion 提问（最多 3 个） | **跳过**，不补充提问 |
| 阶段 3 PRD 设计 | 生成 PRD 后要求用户审阅 | **跳过审阅**，直接采纳 |
| 阶段 4 原型设计 | — | **跳过**（本技能无此阶段） |
| 阶段 5 TFS 分析 | 无交互 | 正常执行 |
| 阶段 6 上传 TFS | AskUserQuestion 确认 | **正常执行：字段 + 标签 + 附件全部执行** |
| 阶段 6.5 完成 AI 分析任务 | 无交互 | 正常执行 |
| 清理阶段 | AskUserQuestion 删除/保留过程文件 | **跳过**，auto-dev 统一管理 docs 目录 |

## 关键注意事项

1. **dev-plan.md 必须生成**：这是 bypass 模式下最关键的输出，编码阶段直接依赖此文件
2. **TFS 上传不可跳过**：评估报告和验收标准必须上传，否则 TFS 工作项缺少关键信息
3. **.analysis-task-id 尽量生成**：缺失不会阻断，但报告阶段会记录警告
