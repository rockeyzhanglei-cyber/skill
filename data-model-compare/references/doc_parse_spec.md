# 数据标准文档解析规范（模型执行 · 输出契约）

> ## 铁律
>
> **解析阶段没有任何程序。** 不存在、也不应存在「读取原始标准文档并理解其格式」的脚本。
> 原始文档（docx / doc / xlsx / pdf / 扫描件）一律由**模型阅读并按本规范输出规范化文件**；
> 固化程序只负责「按契约装载 + 比对」。
>
> 因此本文件是一份**双向契约**：
> - 对模型：规定必须产出什么格式、什么内容，交付前怎么自检；
> - 对程序：规定可以假定输入长什么样（列名集合、取值枚举、结构约束），不得反过来猜文档格式。
>
> 遇到新文档格式 → **改本说明（或扩别名表），不改程序**。

## 1. 职责边界

| 阶段 | 谁做 | 做什么 | 禁止 |
|---|---|---|---|
| ① 读原始文档 | **模型** | 读 docx/doc/xlsx/pdf，识别表、字段、值域、约束 | 不得写脚本"自动提取" |
| ② 规范化输出 | **模型** | 按第 3/4 节产出规范化 MD（必）与 standard.json（选） | 不得省略必填列 |
| ③ 交付自检 | **模型** | 按第 6 节逐条执行，产出自检结论 | 不得跳过自检直接交付 |
| ④ 装载 | 程序 | 按契约读规范化文件 → 内部结构（确定性，无格式猜测） | 不得做格式兼容分支 |
| ⑤ 比对 | 程序 | 字段匹配、约束/长度保护、值域覆盖、报告 | 不得介入语义判断 |
| ⑥ 人工复核 | 人 | 在 Excel 中修正映射 → 回写知识库 | — |

## 3. 规范化 MD 的格式契约（程序按此装载）

### 3.1 骨架

````markdown
# 医护人员信息表 BASE_EMPLOYEE

| 数据元标识符 | 数据元名称 | 约束 | 数据类型 | 表示格式 | 值域 | 说明 |
| --- | --- | --- | --- | --- | --- | --- |
| SYS_SOID | 系统编码 | M | S1 | AN..64 |  | 由平台统一制定的编码 |
| EMPLOYEE_ID | 医护人员唯一标识 | M | S1 | AN..64 |  | 业务系统内部唯一标识 |

# 医护人员科室表 BASE_EMPLOYEE_DEPT

| 数据元标识符 | 数据元名称 | 约束 | 数据类型 | 表示格式 | 值域 | 说明 |
| --- | --- | --- | --- | --- | --- | --- |
| SYS_SOID | 系统编码 | M | S1 | AN..64 |  | 复合主键 |
````

### 3.2 硬性语法规则

1. **表名用一级标题**：`# 中文表名 英文表名`，英文表名可选，两者之间**一个空格**。
   例：`# 入院记录-诊断(辅 D08 标） EMR_ADMISSION_RECORD_DIAGNOSIS`
2. **每张表有且仅有一个标题**；标题即表的边界，两张表之间必须有新标题，不得粘连。
3. **表格语法**：表头行 + 紧随其后的分隔行 `| --- | --- | ... |`，列数必须一致。
4. **列名必须取自第 3.3 节的规范列名集合**——不在集合里的列名程序不认识，会导致整表被丢弃。
5. **同一张表的字段行必须连续**；跨页重复出现的表头允许保留（程序自动跳过），但不能把续表拆成新表。
6. **单元格转义**：单元格内的 `|` 必须替换为 `/`；换行折叠为空格；首尾空格去掉。
7. **空单元格留空**（`|  |`），**不要**写 `-`、`无`、`NULL`、`/`。
8. 表与表之间保留一个空行；文件开头不要加 YAML front matter。

### 3.3 规范列名集合（唯一可用的列名）

| 规范列名 | 含义 | 必填 | 可识别的原文别名（遇到就归一化成左列） |
|---|---|---|---|
| `数据元标识符` | 字段英文代码 | ✅ | 数据元标识、数据元标识符、标识符、标识、字段编码、字段名、字段代码、英文名、英文简称、字段英文 |
| `数据元名称` | 字段中文名 | ✅ | 数据元名称、字段名称、中文名、数据项、名称、字段中文名、字段 |
| `约束` | 必填性 | ✅ | 约束、填报要求、必填、非空、是否必填、填报说明、是否必录 |
| `数据类型` | 类型 | ✅ | 数据类型、类型、数据格式、字段类型 |
| `表示格式` | 长度/格式 | ✅ | 表示格式、长度、数据长度、格式、字段长度 |
| `值域` | 值域代码 | 选填 | 值域、值域代码、字典、代码表、标准编码 |
| `主键` | 主键标记 | 选填 | 主键、是否主键、主键标识 |
| `说明` | 字段说明 | 选填 | 说明、描述、备注、填写说明 |

> ⚠️ 已知陷阱（实战验证）：
> - V6.0 标准写作 **`数据元标识`**（没有"符"字）→ 必须补成 `数据元标识符`；
> - 山东等省平台写作 **`标识符`** → 必须补成 `数据元标识符`；
> - 山东的 **`填报要求` 列取值 "是"** → 列名归一化为 `约束`，取值归一化为 `M`；
> - `数据长度` 是长度不是类型 → 归一化为 `表示格式`。

## 4. 内容契约（每一格写什么）

### 4.1 字段行

| 列 | 取值规范 | 正例 | 反例 |
|---|---|---|---|
| 数据元标识符 | 原始英文代码，原样保留大小写 | `SYS_SOID`、`Drug_dose` | `系统编码`、空 |
| 数据元名称 | 中文名；原文带 `*` 表示必填时**去掉 `*` 并把约束写成 M** | `医护人员唯一标识` | 空 |
| 约束 | **只能** `M` / `C` / `O`；"是/√/Y/必填/非空"→`M`；"条件/有则必填"→`C`；其余→`O` | `M` | `是`、`必填` |
| 数据类型 | 大写：`VARCHAR2/NUMBER/DATE/CHAR/TIMESTAMP/CLOB/INTEGER`；公版写法 `S1/N/D/T/L` 保留原样 | `VARCHAR2`、`S1` | `varchar2(100)` |
| 表示格式 | 只留数字或标准格式串；`VARCHAR2(100)` → `100`；区间保留 `N5,2` | `100`、`AN..64` | `100位` |
| 值域 | 值域代码原文，多个用 `、` 分隔 | `CV02.01.101`、`CC5502.20` | `见值域表` |
| 主键 | `是` / 空 | `是` | `Y`、`√`（统一写 `是`） |
| 说明 | 原文说明，保留关键限定（如"必填，按省平台统一编码填写"） | — | — |

### 4.2 表

- 每张表 = 一个业务实体（对应标准里的一节/一张表），不要把多张表并成一张。
- 英文表名取标准里给出的表码；标准只给中文名时，标题只写中文名（程序可接受）。
- 控制字段表（如"数据上传顺序""填写说明""数据类型表示"）**不要**混入数据表，单独跳过。

### 4.3 值域

- 值域代码写在字段行的 `值域` 列；
- 若标准附带**独立的值域字典分册**，另存为 `target_vd.md`（同目录）供值域维度比对，不要混进字段表。

## 5. 可选：直接产出 standard.json（程序零装载解析）

模型可直接产出结构化 JSON，程序读取后无需任何格式判断：

```json
{
  "source_file": "source_区域平台V6.0医疗服务.md",
  "tables": [
    {
      "name": "BASE_EMPLOYEE",
      "chinese_name": "医护人员信息表",
      "fields": [
        {
          "name": "SYS_SOID",
          "chinese_name": "系统编码",
          "data_type": "S1",
          "length": 64,
          "constraint": "M",
          "description": "由平台统一制定的编码",
          "value_domains": []
        }
      ]
    }
  ]
}
```

字段要求：`length` 为**整数**（无则 0）；`constraint` ∈ {M, C, O}；`value_domains` 为数组，
元素形如 `{"code": "CV02.01.101", "name": "身份证件类别代码"}`。

## 6. 交付前自检（模型必须逐条执行并给出结论）

| # | 检查项 | 通过标准 | 不通过怎么办 |
|---|---|---|---|
| 1 | 表数核对 | 与文档目录 / "表概述"章节声明的数量一致（±2） | 回原文找漏表，常见于跨页续表、附录表 |
| 2 | 字段总数 | 等于各表字段数之和；抽查 3 张表逐字段数一遍 | 检查是否有表被合并或被拆断 |
| 3 | 列名合法 | 所有表头列名都在第 3.3 节集合内 | 按别名表归一化 |
| 4 | 约束取值 | 约束列只出现 M/C/O（全大写单字母） | 按 4.1 归一化 |
| 5 | 必填比例 | `M` 占比既不为 0% 也不为 100% | 说明约束列映射错列或取值未归一化 |
| 6 | 标识符非空 | 数据元标识符列无空值 | 空则用中文名兜底并标注 |
| 7 | 抽样回看 | 随机抽 3–5 张表 × 3 字段，与原文逐字对照 | 发现串行/串列 → 重解析该表 |
| 8 | 结构完整 | 每张表都有 `#` 标题；表头 + 分隔行齐全 | 补齐 |
| 9 | 转义正确 | 单元格内无裸 `|`、无换行 | 替换为 `/` 与空格 |

**交付时必须给出的自检结论**（写在对话里）：

```
源标准：XX 表 / XXXX 字段，必填 XXX（XX%）
目标标准：XX 表 / XXXX 字段，必填 XXX（XX%）
列名归一化：xxx → xxx（N 处）
自检：9 项全部通过 / 第 X 项未通过，原因…
```

## 7. 交付后怎么用（程序侧）

```bash
python3 ~/.workbuddy/skills/data-model-compare/main.py \
  --source "~/data-model-compare-docs/<任务名>/temp/normalized/source_xxx.md" \
  --target "~/data-model-compare-docs/<任务名>/temp/normalized/target_xxx.md" \
  --title "<任务名>"
```

- 输入为 `.md` 时，程序**只做契约装载**（按第 3 节结构读取），不做任何文档格式解析；
- 若第 1/2 项自检未通过（程序解析出 0 表或字段数异常），**不要继续跑比对**——先修规范化文件。

## 8. 常见文档形态处理建议

| 形态 | 处理方式 |
|---|---|
| `.docx` | 直接读；表格跨页断裂时按标题重新聚合，允许保留重复表头 |
| `.doc`（97-2003） | 程序侧无法可靠转换（macOS `textutil` 转 docx/wordml 会丢全部表格，转 odt 丢约 40% 字段）。**先请人在 Word 里另存为 .docx** 再解析 |
| `.xlsx` | 一个 Sheet 一张表时以 Sheet 名为表名；多表共 Sheet 时按标题行切分 |
| `.pdf` | 文字版可直接读；扫描版需 OCR，人工复核后再入比对 |
| 跨页续表 | 保留重复表头即可，不要拆成新表 |
| 值域字典分册 | 单独存 `*_vd.md`，不要混进字段表 |
| 合并单元格 | 展开为每个字段一行；父级限定词（如"入院诊断-"）补进中文名前缀 |

## 9. 变更原则

1. 遇到新表头 / 新取值 → **先改本说明的别名表（3.3）与取值规范（4.1）**，再让模型按新说明产出；
2. **禁止**为了让某份文档"跑通"而在程序里加列名分支；
3. 本说明每次修订，都在下面的修订记录里记一行（日期 + 变更 + 触发的标准）。
