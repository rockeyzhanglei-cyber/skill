## 值域编码查找

新增字段涉及值域时，必须先在同目录下的值域字典文档（Excel格式）中查找：

```
文档路径: {标准文档目录}/区域卫生信息平台数据传输规范 值域字典.xlsx
Sheet: 数据元值域
```

**查找规则**：
1. 搜索是否有现成的值域（如"老年人健康管理等级代码"）
2. 如有现成值域 → 直接引用现有编码
3. 如无现成值域 → 在末尾新增，编码按最大序号顺延

**重要：必须读取整个文件！**
- 使用 `sheet.max_row` 获取总行数
- 搜索范围必须包含所有行（到最后一行）
- 不能只读前500行或部分行，否则会漏掉后面的编码

**Python示例**：
```python
wb = openpyxl.load_workbook(doc_path, read_only=True)
sheet = wb['数据元值域']
total_rows = sheet.max_row  # 获取总行数（可能超过16000行）

# 搜索所有CVA编码
cva_codes = []
for row in sheet.iter_rows(max_row=total_rows):  # 必须遍历所有行
    for cell in row:
        if cell.value and 'CVA-' in str(cell.value):
            matches = re.findall(r'CVA-(\d+)', str(cell.value))
            for m in matches:
                cva_codes.append(int(m))

max_cva = max(set(cva_codes))  # 找最大序号
new_cva = max_cva + 1  # 新增编码 = 最大+1
```

**编码命名规则**：
- 平台自定义值域：CVA-{序号}
- 国标值域：GB/T xxx、CVxx.xx.xxx

## external_id生成规则

元数据的external_id必须按照固定规则生成：

**格式公式**：
```
HDS{标准序号(2位)}{分类序号(2位)}.{数据集序号(3位)}.{元素序号(3位)}
```

**示例**：`HDS0223.001.186`
- 标准序号: 02 (winning-plat-02)
- 分类序号: 23 (个人健康档案)
- 数据集序号: 001 (RESIDENT_ARCHIVE)
- 元素序号: 186 (新字段)

**序号查找方法**：

从BMS后端程序的base_data目录CSV文件中查找：

```
base_data目录: {BMS_ROOT}/src/main/resources/base_data/
```

| 序号类型 | CSV文件 | 列位置 | 字段名 |
|---------|--------|-------|--------|
| 标准序号 | 3__edsm_data_standard.csv | 第9列(索引8) | seq_no |
| 分类序号 | 4__edsm_dataset_category.csv | 第6列(索引5) | seq_no |
| 数据集序号 | 5__edsm_dataset.csv | 第6列(索引5) | seq_no |
| 元素序号 | 6__edsm_dataset_element.csv | 第15列(索引14) | seq_no |

**查找流程**：
1. 根据standard_id（如winning-plat-02）在`3__edsm_data_standard.csv`查找标准序号
2. 根据category_id（如winning-plat-02-个人健康档案）在`4__edsm_dataset_category.csv`查找分类序号
3. 根据dataset_id（如winning-plat-02-RESIDENT_ARCHIVE）在`5__edsm_dataset.csv`查找数据集序号
4. 元素序号使用新字段的seq_no（从Word文档表格位置推断或指定）

**关联关系**：
```
edsm_dataset_element.dataset_id → edsm_dataset.dataset_id
edsm_dataset.category_id → edsm_dataset_category.category_id
edsm_dataset_category.standard_id → edsm_data_standard.standard_id
```

## DDL脚本规范

**注释格式**：使用reg-ddl-generator的标准格式
```sql
/*
{表名中文}[{表名英文}]新增字段：{字段中文}[{字段英文},{数据类型},{约束}]
*/
```
- 约束对应：M→必填，O→应填，C→条件必填

**6.0版本DDL脚本只需包含**：
- ALTER TABLE主表新增字段
- COMMENT ON COLUMN注释

**不需要包含**：
- TRAN表（事务表）字段同步
- LOG表（日志表）字段同步
- 公共字段（SYS_CREATED_AT、SYS_MODIFIED_AT等）
- 上传状态字段

**DDL生成方式**：
1. 使用reg-ddl-generator生成完整DDL（含判断逻辑和TRAN/LOG）
2. 提取注释格式和主表部分（保留判断逻辑）
3. 删除TRAN/LOG相关内容

**DDL示例**（保留判断逻辑）：
```sql
/*
(个人)基本信息[RESIDENT_ARCHIVE]新增字段：老年人健康管理等级代码[ELDER_HEALTH_LEVEL_CODE,VARCHAR(1),应填]
*/

-- (个人)基本信息[RESIDENT_ARCHIVE]新增字段
do $$
begin
    if exists (select 1 from information_schema.tables where table_name = 'resident_archive') then
        if not exists (select 1 from information_schema.columns where table_name = 'resident_archive' and column_name = 'elder_health_level_code') then
            alter table resident_archive add column elder_health_level_code varchar(1) null;
            comment on column resident_archive.elder_health_level_code is '老年人健康管理等级代码';
        end if;
    end if;
end $$;
```

## 修订记录脚本规范

**核心概念**：
- 同一批修订共享同一个`revise_id`（修订主记录ID）
- 同一批修订使用相同的`version`版本号
- 每条变更生成一条`edsm_revise_detail`记录
- 生产环境通过"标准升级模块"读取修订记录，更新数据标准基础数据

### business_code类型

| business_code | 对应数据库表 | 说明 |
|--------------|-------------|------|
| datasetCategory | edsm_dataset_category | 数据集分类 |
| dataset | edsm_dataset | 数据集（表） |
| datasetElement | edsm_dataset_element | 数据集元素（字段） |
| codeSystem | edsm_code_system | 值域定义 |
| valueSet | edsm_value_set | 值域值 |
| metadata | edsm_metadata | 元数据 |

### business_id格式

| business_code | business_id格式 | 示例 |
|--------------|----------------|------|
| datasetCategory | {standard_id}-{category_name} | winning-plat-02-个人健康档案 |
| dataset | {standard_id}-{table_name} | winning-plat-02-RESIDENT_ARCHIVE |
| datasetElement | {dataset_id}-{field_name} | winning-plat-02-RESIDENT_ARCHIVE-elder_health_level_code |
| codeSystem | {code_system_id} | CVA-0306 |
| valueSet | {code_system_id}-{value_no} | CVA-0306-1、CVA-0306-2 |
| metadata | {standard_id}-{metadata_code} | winning-plat-02-ELDER_HEALTH_LEVEL_CODE |

### 修订类型

- `add`：新增
- `edit`：修改
- `delete`：删除

### 新增值域时的修订记录

如果新增字段涉及新增值域，需要生成：
1. `business_code='codeSystem'`：值域定义记录（edsm_code_system表字段）
2. `business_code='valueSet'`：值域值记录（edsm_value_set表字段，每个值一条）
3. `business_code='datasetElement'`：字段记录（edsm_dataset_element表字段）

**重要**：这三类记录共享同一个revise_id！

### 脚本命名

全小写，格式：`V{时间戳}__insert_revise_record_{需求号}.sql`

### 注释规范

使用DDL注释格式作为summary：
```sql
-- {表名中文}[{表名英文}]新增字段：{字段中文}[{字段英文},{数据类型},{约束}]
-- 需求: {需求号}
```

### SQL格式规范

- INSERT语句必须单行，不换行
- 同一个语句写在一行，到下一个语句再换行
- 紧凑格式，无多余空格

### revise_after字段示例

**重要：JSON字段名必须使用驼峰格式，日期必须使用ISO格式！**

1. **字段名格式**：驼峰格式（Java实体类属性名），不是数据库表字段名
2. **日期格式**：ISO格式 `yyyy-MM-dd'T'HH:mm:ss`，如 `2026-06-26T13:35:54`
   - 程序生成：使用Spring注入的ObjectMapper（配置了time-zone: GMT+8），输出格式为 `2026-06-26T13:35:54+08:00`
   - Skill生成：使用无时区格式 `2026-06-26T13:35:54`，Jackson也能正确解析

标准升级模块使用Jackson反序列化JSON，期望：
- 驼峰格式的属性名
- ISO格式的日期（带`T`分隔符）

如果格式不对会报错：
```
# 字段名错误：
Unrecognized field "code_system_id" (class com.winning.dps.rda.common.entity.CodeSystem)

# 日期格式错误（使用空格分隔）：
Cannot parse date "2026-06-26 13:35:54": while it seems to fit format 'yyyy-MM-dd'T'HH:mm:ss.SSSX'
```

## Word文档修订规范

**格式一致性要求**：
- 复制相邻行的格式（单元格宽度、段落格式、字体等）
- 新增内容标记为红色字体（RGB(255,0,0)，XML中为`w:color val="FF0000"`）
- 保持表格整体格式统一（行高、居中、行距、字体、字号）

**具体格式属性**：
- **行高**：设置行高为0.6厘米（340 twips），可实现自适应内容高度
- **段落间距**：单倍行距（spacing line="240" lineRule="auto"）
- **中文版式**：
  - `wordWrap val="0"` - 自动换行
  - `autoSpaceDE val="0"` - 中文和英文间距
  - `autoSpaceDN val="0"` - 中文和数字间距
- **水平居中**：`w:jc val="center"`（继承参考行）
- **单元格垂直居中**：`w:vAlign val="center"`（每个单元格）
- **单元格宽度**：复制相邻行对应单元格的宽度值
- **字体颜色**：新增内容使用红色 `w:color val="FF0000"`

**修订位置**：
- 新增字段应插入到逻辑相邻位置（如KEY_POPULATION_CODE后插入老年人分级字段）
- 不应放在表格末尾

## 修订记录Word文档维护

修订完成后，需要将修订摘要维护到同目录下的修订记录Word文档中。

**文档路径**：
```
{标准文档目录}/区域卫生信息平台数据传输规范 修订记录.docx
```

**表格格式**（4列）：
| 列名 | 内容说明 |
|-----|---------|
| 版本号 | YYYYMMDD格式日期 |
| 修订人 | 修订人员姓名 |
| 类别 | 第XX部分：XXX |
| 修订内容 | 修订摘要描述 |

**修订内容格式参考**：
- 新增表：`新增表：表名中文[表名英文]`
- 新增字段：`表名中文[表名英文]新增字段：字段中文[字段英文,O,S3,N1]`
- 修改字段：`表名中文[表名英文]修改字段：字段中文[字段英文] - 变更说明`
- 删除字段：`表名中文[表名英文]删除字段：字段中文[字段英文]`

### 核心原则

**复制上一行 → 填充内容 → 设置新numId重新编号**

不要手动设置格式属性，复制上一行会自动继承所有格式（行高、行距、中文版式、序号设置等）。

### Python操作示例

```python
from docx import Document
from lxml import etree
from copy import deepcopy

W_NS = '{http://schemas.openxmlformats.org/wordprocessingml/2006/main}'

# 打开修订记录文档
doc_path = '{标准文档目录}/区域卫生信息平台数据传输规范 修订记录.docx'
doc = Document(doc_path)
table = doc.tables[0]

# 获取上一行（最后一行，用于复制格式）
prev_row = table.rows[-1]
prev_numId = None

# 提取上一行修订内容列的numId（用于生成新的numId）
prev_cell = prev_row.cells[3]  # 修订内容列
for para in prev_cell.paragraphs:
    pPr = para._element.find('.//' + W_NS + 'pPr')
    if pPr is not None:
        numPr = pPr.find(W_NS + 'numPr')
        if numPr is not None:
            numId_elem = numPr.find(W_NS + 'numId')
            if numId_elem is not None:
                prev_numId = int(numId_elem.get(W_NS + 'val'))

# 复制上一行创建新行（自动继承所有格式）
new_row_element = deepcopy(prev_row._element)
table._tbl.append(new_row_element)

# 获取新行并填充内容
new_row = table.rows[-1]

# 清空并填充单元格内容
# 版本号（YYYYMMDD）
new_row.cells[0].paragraphs[0].clear()
new_row.cells[0].paragraphs[0].add_run('20260626')

# 修订人
new_row.cells[1].paragraphs[0].clear()
new_row.cells[1].paragraphs[0].add_run('张磊')

# 类别
new_row.cells[2].paragraphs[0].clear()
new_row.cells[2].paragraphs[0].add_run('第02部分：公共卫生')

# 修订内容（带序号的列）
new_row.cells[3].paragraphs[0].clear()
new_row.cells[3].paragraphs[0].add_run('(个人)基本信息[RESIDENT_ARCHIVE]新增字段：老年人健康管理等级代码[ELDER_HEALTH_LEVEL_CODE,O,S3,N1]')

# 设置新的numId以重新开始编号（相当于右键"重新开始编号"）
if prev_numId is not None:
    new_numId = prev_numId + 1  # 使用不同的numId会自动重新从1开始编号
    for para in new_row.cells[3].paragraphs:
        pPr = para._element.find('.//' + W_NS + 'pPr')
        if pPr is not None:
            numPr = pPr.find(W_NS + 'numPr')
            if numPr is not None:
                numId_elem = numPr.find(W_NS + 'numId')
                if numId_elem is not None:
                    numId_elem.set(W_NS + 'val', str(new_numId))

doc.save(doc_path)
```

## 数据标准基础数据检查逻辑

在生成修订记录脚本时，需要检查相关数据是否已存在。**重要：不能只检查初始化CSV脚本，还要检查后续的增量修订记录脚本！**

### 检查范围

数据标准基础数据的来源有两个：
1. **初始化CSV脚本**：`{BMS_ROOT}/src/main/resources/base_data/`目录下的CSV文件
2. **增量修订记录脚本**：`{BMS_ROOT}/src/main/resources/system_sql/rhdp_app/postgresql/`目录下的修订记录脚本

**必须检查两个来源，才能确保数据完整！**

### metadata检查逻辑

判断是否需要生成metadata修订记录时，需要检查`metadata_code`是否已存在：

**检查步骤**：
1. 检查初始化CSV：`7__edsm_metadata.csv`
2. 检查增量修订记录脚本：`system_sql/rhdp_app/postgresql/V*__insert_revise_record*.sql`中`business_code='metadata'`的记录

```python
import os
```

### 项目编码命名规则

**格式**：`PRJ-{3位序号}-{大写拼音简称}`

**规则**：
- **序号**：与项目文件夹的3位数字编号完全对应（001、002、...、016）
- **简称**：项目名称的拼音首字母缩写，2~6个大写字母
  - 地名优先：如深圳罗湖 → SZLH，浙江 → ZJ，安徽 → AH
  - 项目特征：如北京电子病历 → BJDZ（北京电子），武汉疫情 → WH

### 项目化修订记录生成要点

1. **文档路径匹配**：
   - 需求分析阶段，根据需求中的版本和项目信息，定位到项目化目录下的对应项目子目录
   - 例如：需求提到"深圳罗湖"、项目编码"PRJ-001-SZLH" → 定位到 `02 标准规范（项目化）/001 深圳市罗湖区妇幼保健院/`

2. **修订记录脚本**：
   - INSERT `edsm_revise_record` 时，`is_standard=0`，`project_code` 填项目编码
   - `edsm_revise_detail` 与公版格式相同，无差异

3. **修订记录Word文档**：
   - 每个项目目录下有自己的 `修订记录.docx`
   - 修订操作与公版相同（复制上一行 → 填充 → 新numId重新编号）

4. **DDL脚本**：
   - 数据库类型为 greenplum（与公版一致）
   - 提交到与公版相同的 BMS 目录
