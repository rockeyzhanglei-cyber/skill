# 基准库 vs 目标库结构比对规则

## 核心目标
保证目标库结构与基准库结构一致，使目标库能够接收与基准库相同的数据。

## 比对维度

### 1. 缺失字段（基准库有，目标库没有）
判断逻辑：
- **基准库中存在的字段，在目标库中不存在** → **标记为问题**

修复方式：
- 在目标库新增字段（ADD COLUMN）
- 新增字段时，全部为NULL（可空），不允许NOT NULL，不加DEFAULT
- 理由：保持与基准库相同的数据存储能力，由业务逻辑保证数据完整性

### 2. 多余字段（目标库有，基准库没有）
判断逻辑：
- **可空字段**（NULLABLE=Y） → **忽略**（不影响数据入库）
- **不可空字段 + 有默认值** → **忽略**（数据库自动填充，不影响入库）
- **不可空字段 + 无默认值** → **标记为问题**（多余必填字段）

原因：
- 如果字段可空，第三方不传时数据库允许为NULL，不影响入库
- 如果字段不可空但有默认值，数据库会自动填充，不影响入库
- 如果字段不可空且无默认值，第三方不传时报错"字段不能为NULL"

### 3. 字段类型不一致
判断逻辑：
- **类型不匹配** → **标记为问题（不安全修改）**

原因：
- 类型变更可能涉及数据转换，需要人工确认
- 类型不一致会导致数据入库失败或数据丢失

修复建议：
- 注释状态，需人工确认后执行
- 每条必须包含完整可执行的ALTER语句

### 4. 字段长度/精度不一致
判断逻辑：
- **目标库长度/精度 >= 基准库** → **忽略**（能存下，数据不会截断）
- **目标库长度/精度 < 基准库** → **标记为问题（长度/精度不足）**

原因：
- 基准库能存下的数据，目标库也必须能存下
- 如果目标库长度/精度不足，数据可能截断或报错

修复方式：
- 扩大字段长度/精度（MODIFY扩大）
- 属于安全修改，可直接执行

### 5. 可空性不一致
判断逻辑：
- **基准库允许NULL，目标库不允许NULL（NOT NULL）** → **标记为问题**
- **基准库不允许NULL（NOT NULL），目标库允许NULL** → **标记为问题**

原因：
- 可空性不一致会导致数据完整性检查失败
- 基准库允许NULL的字段，目标库也必须允许NULL

修复方式：
- 如果基准库允许NULL，目标库需要改为允许NULL（MODIFY ... NULL）
- 如果基准库不允许NULL，目标库需要改为不允许NULL（MODIFY ... NOT NULL）
- 需要人工确认，标记为不安全修改

### 6. 默认值不一致
判断逻辑：
- **基准库有默认值，目标库没有默认值** → **标记为问题**
- **基准库没有默认值，目标库有默认值** → **标记为问题**

原因：
- 默认值不一致会导致数据填充行为不同
- 基准库有的默认值，目标库也必须保持一致

修复方式：
- 添加默认值（ALTER TABLE ... MODIFY ... DEFAULT ...）
- 删除默认值（ALTER TABLE ... MODIFY ... DEFAULT NULL）
- 需要人工确认，标记为不安全修改

## 修复脚本安全分类

### 安全修改（直接可执行，无需人工确认）
- 新增字段（ADD COLUMN）—— 全部为NULL
- 扩大字段长度/精度（MODIFY扩大，数据不会截断）

### 不安全修改（注释状态，需人工确认后放开）
- 数据类型变更（可能丢失数据）
- 缩小字段长度/精度（可能导致数据截断）
- 修改可空性（NOT NULL ↔ NULL）
- 修改默认值
- 修改主键类型或长度（可能影响索引和约束）

## 脚本格式要求
- 每条不安全修改必须在注释中说明：修改理由、当前值、期望值、风险提示
- 不安全修改放在脚本最前面，注释状态
- 安全修改放在后面，可直接执行
- 脚本末尾附统计行：不安全=N, 安全=N
