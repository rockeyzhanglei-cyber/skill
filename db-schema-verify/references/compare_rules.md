# 标准文档 vs 库表结构比对规则

## 核心目标
保证第三方按文档传输数据时，数据能100%进入数据库，不会因为字段缺失、类型不匹配、长度不足或精度问题导致报错。

## 比对规则

### 1. 基准库多余的字段（文档中没有）

判断逻辑：
- **非必填字段**（约束=O/C） → 忽略
- **必填字段**（约束=M） + **有默认值** → 忽略（这是逻辑字段，插入时会自动填充）
- **必填字段**（约束=M） + **无默认值** → **标记为问题**（多余必填字段）

原因：
- 第三方按文档传数据时，不会传这些多余字段
- 如果字段非必填，数据库允许为NULL，不影响入库
- 如果字段必填但有默认值，数据库会自动填充默认值，不影响入库
- 如果字段必填且无默认值，数据库会报错"字段不能为NULL"，导致入库失败

### 2. 字段长度/精度不一致

判断逻辑：
- **库里长度/精度 >= 文档要求** → 忽略（能存下）
- **库里长度/精度 < 文档要求** → **标记为问题**（长度/精度不足）

原因：
- 第三方按文档传数据，数据长度/精度符合文档要求
- 如果库里长度/精度 >= 文档要求，数据肯定能存下
- 如果库里长度/精度 < 文档要求，数据可能存不下，导致截断或报错

### 3. 字段类型不一致

判断逻辑：
- **类型不匹配** → **标记为问题**

原因：
- 第三方按文档传的数据类型，与库里字段类型不匹配，会导致类型转换错误

### 4. 基准库缺失的字段（文档中有，库里没有）

判断逻辑：
- **文档中必填字段**（约束=M） → **标记为问题**（缺失必填字段）
- **文档中非必填字段**（约束=O/C） → **标记为问题**（缺失字段）

原因：
- 缺失字段会导致第三方传的数据无法存储，即使是非必填字段，也应该在库中存在

修复方式：
- **新增字段时，全部为NULL（可空），不允许NOT NULL，不加DEFAULT**
- 即使文档中标注约束为M，修复新增时也只能加NULL
- 理由：第三方不传就不入库，由业务逻辑保证，不要在这里做强约束

## 约束标识说明

Word文档中的约束标识：
- **M** = Mandatory（必填）
- **O** = Optional（可选）
- **C** = Conditional（条件必填）

## 数据类型映射

> ⚠️ 完整的数据类型映射规则请参考 `references/type_mapping.md`
> 
> 本规则文件仅列出常用映射：
> - S1/S2/S3/S（字符型）→ VARCHAR2
> - N（数值型）→ NUMBER
> - D（日期型）→ DATE
> - DT（日期时间型）→ DATE/TIMESTAMP

格式说明：
- **AN..n** = 字母数字混合，最大长度n
- **N{p,s}** = NUMBER(p,s)
- **N{n}** = 当DataType为S1/S2/S3时是VARCHAR2(n)，当DataType为N时是NUMBER(n)
